# The Receipt Gap · Questions

11 November 2026 (HKT), Codex survey / protocol v0.1 draft. Append dated entries in later authorized work; preserve earlier questions. These are hypotheses and review points, not observed agent results or additional authorized experiments.

## Questions for protocol review

- Is the ten-percentage-point exact-once-completion tolerance acceptable for a synthetic safety benchmark? It is explicit in RQ1; lowering duplication at the price of missed jobs must remain visible even if it passes that tolerance.
- Does offering a null key best isolate voluntary safety-tool use? A mandatory stable key would test a different contract, while harness-inserted keys would remove the behavior of interest.
- Are conservative duplicate-or-failure penalties plus the actual-duplicate contrast sufficient to expose interface failures without claiming imaginary duplicate effects? Keep actual event truth and operational penalties separate.
- Does the reporting rule fairly separate admission of real duplicates from truthful uncertainty? Null can be epistemically correct yet operationally a miss. Show both instead of calling every null dishonest.
- Can the installed ClaudeCLI enforce both the required JSON Schema and an accounted-output ceiling at medium effort? Outer CLI JSON is not a guarantee that the scientific reply is valid JSON. No frontier dispatch until this is resolved offline and the actual payload field is fixed.
- Will 24 frontier episodes still fit the USD11 worst-reservation allocation after final reviewed prompts and actual CLI constraints are known? Draft byte-envelope sizing fits at USD6.322176, but assumes historical rates, a 512-token enforced output ceiling and the 826-token hidden-input allowance. Those are not current transport guarantees.
- Is the 826-token historical hidden-input allowance still defensible for the exact transport version? What supported bound and headroom protect the under-USD40 limit if it has changed? Do not discover feasibility through paid experimental probes.

## Research questions carried by this design

- After an unknown receipt, does the agent reuse the original key, invent a new one, omit it, check status, or abandon the job? Which behavior explains completion and duplicate effects without attributing an unobserved internal intention?
- Does a reliable status tool help enough to offset one of ten scarce decisions? It reveals at least one effect, not whether a duplicate has already occurred.
- Can a model complete all four jobs with little confirmation and still accurately distinguish what happened from what it knows? The final report has code truth, while the agent has partial evidence.
- Does payment wording change risk-taking when the underlying simulator is identical to notifications? A framing effect would concern these instructions, not actual financial behavior.
- Does the 0% receipt-loss control still duplicate because of ordinary request failures or agent confusion? There is no travel delay here, so the toy's slow-message mechanism cannot explain such duplicates.
- Is protection caused by using a key consistently, or by stopping earlier? Exact-once completion, sends and unused decisions must accompany any duplicate-rate reduction.
- If no true duplicate occurs, what can reporting performance establish? General report correctness remains measurable, but duplicate-admission recall is UNKNOWN rather than a perfect score.
- How much response variance remains with fixed local seeds and digests? This version records first responses only; a future separately registered replay sample could measure it without replacing observations.

## Extensions outside v0.1

- What happens when keys expire, a ledger resets, or effect/key atomicity fails? These are counterexamples already motivated by the toy; permanent keys here cannot establish production exactly-once guarantees.
- Would charging keyed attempts extra, as the toy does, reverse the completion result? Equal decision opportunities and equal resource costs answer different questions.
- Do delays and in-flight requests cause agents to retry before a possible acknowledgement can arrive? A later delayed environment needs its own time model and registered horizon.
- Can report-only and trace monitors detect these duplicates, and where should they abstain? Any monitor extension needs code-certified evidence sufficiency, a strict verdict contract, at least 200 judgments and abstention-as-miss co-primary detection.
- Does a handoff to another agent preserve the intent key and evidence of uncertainty, or convert uncertainty into a confident resend? This connects to coordination research but is outside this one-agent task.
- What would justify a larger frontier replication? A specific unresolved behavioral question and a newly measured budget, not a desire to rescue a failed local prediction or significance test.
